## ۱. محدودیت‌های فنی

### ۱.۱. هاست و سرور

| محدودیت               | توضیح                                                        | راه‌حل                             |
| --------------------- | ------------------------------------------------------------ | ---------------------------------- |
| **بدون SSH**          | دسترسی SSH روی هاست اشتراکی cPanel غیرفعال است               | استفاده از FTP + GitHub Actions    |
| **بدون Cron پیشرفته** | Cron هاست محدود است و نمی‌تواند PHP با ورودی پیچیده اجرا کند | یادآوری با ICS به Google Calendar  |
| **بدون دیتابیس**      | MySQL موجود است ولی تصمیم شد از JSON استفاده شود             | فایل JSON در `data/` + بکاپ خودکار |
| **PHP 7.4+**          | حداقل نسخه                                                   | استفاده از آرایه‌های کوتاه `[]`    |
| **بدون Composer**     | autoload ندارد                                               | require دستی فایل‌ها               |
| **بدون Web Push**     | Service Worker محدود است در هاست اشتراکی                     | ICS + PWA (در فاز بعد)             |

### ۱.۲. امنیت

| محدودیت           | توضیح                             | راه‌حل                               |
| ----------------- | --------------------------------- | ------------------------------------ |
| **CSRF نرم**      | توکن CSRF در session ذخیره می‌شود | توکن در header + verify در `api.php` |
| **رمز عبور ساده** | bcrypt در JSON                    | `$2y$10$...` در `settings.json`      |
| **Rate Limiting** | بدون Redis، در فایل ذخیره می‌شود  | شمارنده در `data/rate_limit.json`    |
| **بدون 2FA**      | برای سادگی                        | در فاز بعد اضافه شود                 |

### ۱.۳. ذخیره‌سازی

| محدودیت                   | توضیح                                  | راه‌حل                         |
| ------------------------- | -------------------------------------- | ------------------------------ |
| **حجم فایل JSON**         | محدود به ۱۰ مگابایت (در عمل ۱ مگابایت) | Archive سالانه                 |
| **بدون concurrent write** | JSON قفل ندارد                         | `flock` در `data_write()`      |
| **بدون نسخه‌بندی خودکار** | Git فقط روی GitHub است                 | بکاپ روزانه در `data/backups/` |

## ۵. چک‌لیست قبل از تصمیم‌گیری

قبل از اضافه کردن هر فیچر جدید، این سوالات را بپرس:

- [ ] آیا این فیچر با محدودیت‌های فنی سازگار است؟
- [ ] آیا با اصول کوچینگ همخوانی دارد؟
- [ ] آیا کاربر می‌تواند در روز بد (سطح بقا) از آن استفاده کند؟
- [ ] آیا پیچیدگی را زیاد می‌کند؟
- [ ] آیا ADR برای آن نوشته شده؟
